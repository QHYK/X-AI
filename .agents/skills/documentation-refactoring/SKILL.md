# X-AI-field 文档体系审计与重构

## 何时使用

- 重大功能迭代完成后，需要系统核对文档、测试、脚本和实施状态。
- 用户要求对整个 `docs/` 或指定领域开展文档审计、去重、合并、拆分或迁移。
- 多份规范出现冲突、过期或职责混乱，需要恢复唯一可信的 Source of Truth。

普通功能开发、单个文档的日常同步遵循 `AGENTS.md`，不启动本 Skill。

## 输入与事实边界

1. 先读 `AGENTS.md` 和 `docs/00-index.md`；按任务范围逐步读取相关规范，不默认全文加载所有文档。
2. 确定审查范围：重大迭代应结合 Git commit/diff、验收结论、相关代码、Schema、测试和 `package.json`；专项文档整理则以指定领域为边界。范围不清时先询问或明确 Git 基线假设。
3. 聊天总结和旧文档是待核实线索，不是实现证据；不要假设 Coding Agent 能访问聊天历史。
4. 区分 **Implemented / Planned / Deprecated** 和 **已部署 / 未部署**。未实现不代表已批准设计可以删除；有 Schema 预留也不代表功能已经实现。
5. 代码与文档冲突时，记录双方证据并核对已批准决策，不擅自认定代码或文档必然正确。

## 工作流

### 1. 确定审计范围并建立变更地图（只读）

- 优先使用用户指定的 Git Tag 或 Commit 作为本轮审计 Baseline；未指定时，可参考当前分支历史中最近的 `v*` Tag。
- 对比 Baseline 与当前代码状态，结合 Baseline 之后的 Commit Message 及可获取的项目开发历史，识别本轮实际发生的功能和工程变更。Commit Message 用于理解意图，以实际代码和配置验证变更事实。
- 根据变更结果建立业务主题清单，确定需要审查的 Source of Truth；必要时检查相关依赖及未提交修改。
- 如果 Baseline 不明确或存在重大范围歧义，向用户确认。

审计报告应说明使用的 Baseline、主要变更主题及实际审查范围。

### 2. 统一审计（只读）

围绕每项事实检查：

- **正确性**：文档、代码、已批准设计及部署状态是否一致。
- **权威归属**：是否有一个主要 Source of Truth；其他位置是否只保留必要摘要与链接。
- **完整性**：失败/恢复、并发、权限、版本绑定、部署等关键契约是否遗漏。
- **精简性**：是否存在过时 Planned、重复规则、一次性交付记录、静态 Prompt 副本或无用说明。
- **工程资产**：测试、Fixture、Migration、Seed、历史脚本、恢复工具及 CI 是否仍有独立价值；没有证据不删除。
- **导航**：索引、README/AGENTS 入口、相对链接、命令和标题锚点是否有效。

### 3. 形成决策清单并等待批准

每项问题给出：事实/问题、代码与文档证据、严重程度、建议的唯一 Source of Truth、拟采取的动作（保留/修正/迁移/合并/链接/删除）、风险及是否需要用户决策。

对结构调整给出**迁移映射**：原章节 → 目标文档/章节 → 保留或删除的理由；标出可能丢失的关键设计、操作步骤和引用。

区分 **必须修复 / 可选精简 / 后续技术债 / 明确不处理**。存在产品或技术决策歧义时先问用户。**本阶段不修改文件，等待明确批准。**

### 4. 按批准范围协调实施

- 按业务主题一次性处理同一章节的错误、重复与过时内容，避免反复改写。
- 优先更新已有 Source of Truth；只有形成长期独立职责时才新增文档。
- 迁移时保留仍有效的决策、约束、示例和操作命令；允许其他文档保留简短摘要与链接，不机械删除所有相似表述。
- 更新 `docs/00-index.md`、README/AGENTS 中受影响的导航及所有相关引用。
- 文档整理不默认授权修改业务代码、Schema、Migration、Prompt Registry 或生产数据。测试、脚本等工程资产的删除或重构需要单独批准。

### 5. 验证与交付

- 对照迁移映射核查关键事实无遗漏，检查 diff、索引、Markdown 链接、标题锚点、代码块、图示和旧路径引用。
- 核对 JSON/SQL/命令示例与当前实现；运行 `git diff --check` 及仓库已有的相关静态检查。仅在必要时运行与改动相关的 Mock/契约测试。
- 不默认执行付费 LLM、真实数据库写入、Migration 或部署。
- 按决策清单报告已解决、未解决及需人工确认的事项，简述修改文件与验证结果；不为一次性交付额外创建永久 Markdown 报告。

## X-AI-field 特有边界

- 文档具体路径与职责以当前 `docs/00-index.md` 为准，不在 Skill 中维护第二份完整目录表。
- `08-source-list.md` 属于来源配置，不因普通文档整理修改。
- Prompt Registry 的生产 Published 文案以数据库版本为准；Prompt Spec 主要维护契约，不默认复制或修改生产 Prompt。
- Daily 与 Discovery 是不同 Workflow；文档审查不得悄然改变运行行为。
- 对恢复脚本、Fixture、Seed、Migration 和历史测试保守处理：先证明无独有用途，再提议清理。

## 完成标准

**事实正确、权威清晰、关键知识不丢失、入口可用、改动最小。** 文档数量减少不是独立的成功指标。
